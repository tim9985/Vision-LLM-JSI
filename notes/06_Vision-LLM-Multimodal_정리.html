yolo_to_json.py탐지 결과 → Dictionary → JSON
model = YOLO("src/models/YOLO/yolo11n_int8.engine")   # 04에서 만든 INT8 엔진

image = cv2.imread("src/images/city.png")
height, width = image.shape[:2]

results = model.predict(source=image, conf=0.25, iou=0.5, verbose=False)
result = results[0]

objects = []

for box in result.boxes:
    class_id   = int(box.cls[0].item())
    confidence = float(box.conf[0].item())
    x1, y1, x2, y2 = box.xyxy[0].cpu().tolist()      # GPU 텐서 → CPU → 리스트

    objects.append({
        "class": result.names[class_id],              # 인덱스 → 클래스 이름
        "confidence": round(confidence, 3),
        "bbox": {"x1": int(x1), "y1": int(y1),
                 "x2": int(x2), "y2": int(y2)},
    })

vision_dict = {"image_width": width, "image_height": height, "objects": objects}

with open("src/output/vision_data.json", "w", encoding="utf-8") as file:
    json.dump(vision_dict, file, ensure_ascii=False, indent=4)
01 세션이 여기서 쓰인다

json.dump(..., ensure_ascii=False, indent=4) — 01 세션에서 배운 그 인자들입니다. ensure_ascii=False가 없으면 한글 클래스명이 유니코드 이스케이프로 저장됩니다.

.cpu().tolist()도 03 세션의 그 패턴입니다 — GPU 텐서는 Python 리스트로 바로 못 바꿉니다.

json_to_text.pyTemplate 기반 자연어 변환
def detections_to_text(json_path):
    with open(json_path, "r", encoding="utf-8") as file:
        vision_data = json.load(file)

    objects = vision_data["objects"]

    if len(objects) == 0:
        return "현재 탐지된 객체가 없습니다."       # 빈 결과도 문장으로!

    sentences = []
    for index, obj in enumerate(objects, start=1):
        sentences.append(
            f"{index}번 객체는 {obj['class']}이며, confidence는 {obj['confidence']:.2f}입니다."
        )

    return "\n".join(sentences)
POINT

탐지된 객체가 없을 때 빈 문자열이 아니라 문장을 반환하는 것이 중요합니다. Context가 비어 있으면 LLM이 아무 말이나 지어낼 여지가 생깁니다 — "없습니다"라고 명시해 줘야 합니다.

vision_llm.py실시간 루프 — 키 입력으로 LLM 호출
yolo = YOLO(YOLO_MODEL_PATH)
llm  = Llama(model_path=GEMMA_MODEL_PATH, n_gpu_layers=-1,
             n_ctx=2048, n_batch=32, n_ubatch=32, verbose=False)
cap  = cv2.VideoCapture(pipeline, cv2.CAP_GSTREAMER)

while True:
    ret, frame = cap.read()
    key = cv2.waitKey(1) & 0xFF

    if not ret or key == ord("q"):
        break

    # 1~3. 매 프레임 YOLO 탐지 + 화면 출력 + Dictionary 변환
    result = yolo.predict(source=frame, conf=0.25, iou=0.5, verbose=False)[0]
    cv2.imshow("YOLO + Gemma", result.plot())
    vision_dict = {...}

    # 4~6. 'l' 키를 누른 프레임에서만 LLM 호출
    if key == ord("l"):
        with open(JSON_PATH, "w", encoding="utf-8") as file:
            json.dump(vision_dict, file, ensure_ascii=False, indent=4)

        vision_text = detections_to_text(JSON_PATH)

        response = llm.create_chat_completion(
            messages=[
                {"role": "system", "content": "Instruction: ... Constraint: ... Output Format: ..."},
                {"role": "user",   "content": f"Context:\n{vision_text}"},
            ],
            max_tokens=150, temperature=0.7,
        )
        print(response["choices"][0]["message"]["content"])
왜 매 프레임이 아니라 키 입력인가

LLM 추론은 수 초가 걸립니다. 매 프레임 호출하면 영상이 완전히 멈춥니다. 그래서 탐지는 매 프레임, LLM은 사용자가 요청할 때만 — 이 비대칭이 다음 절(프로세스 분리)의 출발점입니다.

B

프로세스 분리

파일을 통해 두 프로그램을 잇는다

Vision과 LLM을 하나의 프로세스에서 순차 실행하면, LLM 추론 중에는 새 카메라 프레임과 탐지 결과를 처리하지 못해 최신 정보를 놓칩니다. LLM의 지연이나 오류가 Vision까지 함께 망가뜨리기도 합니다.

그래서 실제 실시간 시스템에서는 각 기능을 독립 프로세스로 분리하고, JSON 파일로 정보를 주고받습니다.

통합 (한 프로세스)

  • LLM 추론 중 영상 정지
  • LLM 오류가 Vision까지 중단
  • 구현은 간단

분리 (두 프로세스)

  • Vision은 계속 30 FPS 유지
  • 한쪽이 죽어도 다른 쪽은 생존
  • JSON 파일이 인터페이스
writer.py⚠ 임시 파일에 쓰고 os.replace로 교체
JSON_PATH      = "src/output/vision_data.json"
TEMP_JSON_PATH = "src/output/vision_data_tmp.json"

if key == ord("l"):
    # 4. 먼저 '임시' 파일에 저장
    with open(TEMP_JSON_PATH, "w", encoding="utf-8") as file:
        json.dump(vision_dict, file, ensure_ascii=False, indent=4)

    # 5. 작성이 끝난 뒤에 실제 파일로 '교체'
    os.replace(TEMP_JSON_PATH, JSON_PATH)
이 절의 핵심 — 왜 임시 파일을 거치나

json.dump는 파일에 조금씩 나눠 씁니다. 읽는 쪽이 하필 그 중간에 파일을 열면 잘린 JSON을 읽어 JSONDecodeError가 납니다.

os.replace()는 원자적(atomic)입니다 — 파일이 통째로 바뀌거나 아예 안 바뀌거나 둘 중 하나라, 읽는 쪽은 언제 읽어도 완전한 JSON을 봅니다. 이것이 파일로 프로세스를 잇는 표준 기법입니다.

읽는 쪽(reader.py)

JSON 파일의 수정 시각(os.path.getmtime)을 주기적으로 확인하다가, 값이 바뀌면 새 탐지 결과가 들어온 것으로 보고 읽어서 Gemma에 넘깁니다. time.sleep()으로 폴링 간격을 둡니다.

C

Image 기반 멀티모달

텍스트 대신 이미지를 직접 넘긴다
용어
  • 모달리티(Modality) — 정보를 표현하는 데이터의 형태. Text · Image · Audio · Video
  • 멀티모달(Multimodal) — 서로 다른 두 가지 이상의 Modality를 함께 처리
  • A장은 Image → Text → LLM(중간에 텍스트를 거침), 여기서는 Image → LLM(직접)
multimodal.pymmproj + base64 data URI
import base64
from llama_cpp import Llama
from llama_cpp.llama_chat_format import Gemma4ChatHandler

# 05에서 함께 받아 둔 mmproj 파일이 여기서 쓰인다
chat_handler = Gemma4ChatHandler(clip_model_path=MMPROJ_PATH)

llm = Llama(
    model_path=MODEL_PATH,
    chat_handler=chat_handler,      # ← 이것만 추가하면 이미지 입력이 가능해진다
    n_gpu_layers=-1, n_ctx=2048, n_batch=32, n_ubatch=32, verbose=False,
)

# 이미지 → JPEG 바이트 → base64 → data URI
image = cv2.imread(IMAGE_PATH)
success, buffer = cv2.imencode(".jpg", image)

if not success:
    raise RuntimeError("이미지 인코딩에 실패했습니다.")

image_base64 = base64.b64encode(buffer).decode("utf-8")
image_data   = "data:image/jpeg;base64," + image_base64

response = llm.create_chat_completion(
    messages=[
        {"role": "system", "content": "Instruction: ... Constraint: ... Output Format: ..."},
        {
            "role": "user",
            "content": [                                  # ← content가 '리스트'가 된다!
                {"type": "text",      "text": "현재 카메라 이미지를 설명하시오."},
                {"type": "image_url", "image_url": {"url": image_data}},
            ],
        }
    ],
    max_tokens=150, temperature=0.7,
)
구조가 바뀌는 지점

텍스트만 넣을 때 content는 문자열이었습니다. 멀티모달에서는 리스트가 되고, 각 항목이 {"type": ...}를 가진 딕셔너리입니다. 이미지는 파일 경로가 아니라 base64로 인코딩된 data URI로 넘깁니다.

D

ROI 전달

전체가 아니라 관심 영역만

프레임 전체를 넘기면 LLM이 봐야 할 것이 너무 많습니다. YOLO로 신호등만 찾아 crop해서 넘기면 훨씬 정확하게 답합니다 — 04 세션의 Section Project(신호등 색 판단)를 이번엔 규칙이 아니라 LLM으로 푸는 셈입니다.

roi_traffic_light.py탐지 → 선택 → crop → 전달
results = yolo.predict(
    source=image,
    conf=0.015,      # 신호등은 작아서 임계값을 크게 낮춘다
    iou=0.5,
    classes=[9],     # COCO 9번 = traffic light
    verbose=False,
)
result = results[0]

if len(result.boxes) == 0:
    raise RuntimeError("신호등이 탐지되지 않았습니다.")

# 가장 '위에' 있는 박스 선택 (y1이 최소) — 화면 위쪽 신호등을 고르는 규칙
selected_box = min(result.boxes, key=lambda box: float(box.xyxy[0][1].item()))
x1, y1, x2, y2 = selected_box.xyxy[0].cpu().tolist()
x1, y1, x2, y2 = int(x1), int(y1), int(x2), int(y2)

# 이미지 경계 밖으로 나가지 않도록 clamp
height, width = image.shape[:2]
x1, y1 = max(0, x1), max(0, y1)
x2, y2 = min(width, x2), min(height, y2)

traffic_light_image = image[y1:y2, x1:x2].copy()      # NumPy 슬라이싱 = crop

if traffic_light_image.size == 0:
    raise RuntimeError("BBox 이미지를 만들 수 없습니다.")
strict_prompt.py한 단어만 받아내는 Prompt
{
    "role": "system",
    "content": """
                Instruction:
                주어진 신호등 이미지의 현재 색을 판단하시오.

                Constraint:
                반드시 다음 세 가지 중 하나만 대답하시오.
                빨간불
                노란불
                파란불

                다른 설명이나 문장을 추가하지 마시오.

                Output Format:
                한 단어.
               """
}

# temperature=0.0 — 판단 작업이므로 무작위성을 없앤다
# max_tokens=20  — 한 단어만 받으면 되므로 짧게
Prompt 설계 3종 세트

① 선택지를 명시(빨간불/노란불/파란불), ② 금지 사항을 명시("다른 설명 추가 금지"), ③ temperature=0.0. 이 셋을 같이 써야 파싱 가능한 출력이 안정적으로 나옵니다. .strip()으로 앞뒤 공백을 제거하는 것도 잊지 마세요.

이미지도 파일로 프로세스를 잇는다

B장의 JSON과 똑같이, ROI 이미지도 cv2.imwrite(TEMP_IMAGE_PATH, ...) → os.replace(TEMP_IMAGE_PATH, OUTPUT_IMAGE_PATH)로 원자적 교체를 합니다. 텍스트든 이미지든 같은 패턴입니다.

import subprocess

def speech_to_text():
    subprocess.run(
        [
            "pasuspender", "--",        # PulseAudio를 잠시 멈춰 장치 점유 해제
            "arecord",
            "-D", MIC_DEVICE,
            "-f", "S16_LE",
            "-r", "16000",
            "-c", "1",
            "-d", str(RECORD_SECONDS),
            AUDIO_FILE,
        ],
        check=True,                    # 실패하면 예외 발생
    )

    result = subprocess.run(
        [
            WHISPER_PATH,
            "-m", WHISPER_MODEL,
            "-f", AUDIO_FILE,
            "-l", "ko",
            "--no-timestamps",
        ],
        text=True,                     # 결과를 문자열로 (bytes 아님)
        capture_output=True,           # stdout을 잡아둔다
        check=True,
    )

    return result.stdout.strip()
subprocess 3인자

check=True 실패 시 예외 · text=True 출력을 문자열로 · capture_output=True stdout 캡처. 이 셋이 있어야 result.stdout으로 인식 결과를 받을 수 있습니다. 명령을 문자열이 아니라 리스트로 넘기는 것도 중요합니다 — 공백이 든 경로도 안전하게 처리됩니다.

왜 가상환경을 나누나

Piper는 자체 의존성(특히 ONNX 런타임 계열)을 요구해, 지금까지 04·05에서 힘들게 맞춰 놓은 NumPy 1.23.0 / OpenCV / ultralytics 조합을 깨뜨릴 수 있습니다. 그래서 아예 별도 venv에 격리하고, 메인 코드에서는 .piper_venv/bin/python을 subprocess로 호출합니다.

tts.py합성 → 재생
PIPER_PYTHON  = ".piper_venv/bin/python"     # ← 다른 venv의 python을 직접 지목
PIPER_MODEL   = "src/models/Piper/ko_KR-kss-medium.onnx"
OUTPUT_FILE   = "src/audio/response.wav"
SPEAKER_DEVICE = "plughw:2,0"

def text_to_speech(text):
    # 1) 텍스트 → wav 파일
    subprocess.run(
        [PIPER_PYTHON, "-m", "piper",
         "-m", PIPER_MODEL,
         "-f", OUTPUT_FILE,
         "--", text],          # "--" 이후는 옵션이 아니라 '내용'
        check=True,
    )

    # 2) wav 파일 재생
    subprocess.run(["aplay", "-D", SPEAKER_DEVICE, OUTPUT_FILE], check=True)
POINT

"--"는 "여기서부터는 옵션이 아니다"라는 표시입니다. 합성할 문장이 -로 시작해도 옵션으로 오해받지 않습니다.
